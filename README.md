# My List VPN

Десктоп-клиент для **Windows и Linux (Fedora)** с двумя режимами подключения:

- **TUN** — весь трафик компьютера идёт через сервер (системный сетевой
  адаптер), не только браузер;
- **PROXY** — локальный SOCKS5/HTTP-прокси, без прав администратора/root:
  прописывается вручную (или, на Windows, автоматически) в браузер/приложение.

Режим выбирается переключателем **TUN/PROXY** прямо на главном экране перед
подключением.

Поддерживает:

- **vless://** и **trojan://** ссылки (Xray-core: TCP/WS/gRPC, TLS и REALITY,
  XTLS-flow)
- **Ссылки-подписки** (http/https) — программа скачивает и раскладывает их
  на все найденные внутри vless/trojan/WireGuard-конфиги (построчно или
  одним base64-блоком, как отдают панели вроде 3x-ui/Marzban) и добавляет
  сразу все серверы одной вставкой
- **AmneziaWG** конфиги (в том числе экспортированные из приложения Amnezia
  как JSON — программа сама найдёт `[Interface]/[Peer]` внутри) — **только
  режим TUN**, у WireGuard-протокола нет понятия «прокси»
- Обычный **WireGuard** `.conf`

Доступ в приложение защищён **локальным аккаунтом** (email + пароль): пароль
не отправляется никуда и не хранится — он превращается в ключ, которым
шифруется список ваших серверов (AES-256-GCM). Ни хостинга, ни базы данных
нет, всё живёт на этом компьютере. Если пароль забыт — восстановить его
нельзя, только сбросить аккаунт (кнопка на экране входа), при этом
сохранённые серверы удаляются.

## Права администратора/root — только для TUN

Режим **PROXY** прав не требует вообще — приложение можно запускать и
пользоваться им сразу.

- **Windows**: собранный `.exe` запускается без UAC (`asInvoker`). Когда
  нужен именно TUN, нажмите **«Перезапустить от администратора»** в баннере
  вверху — это единственное место, где запрашивается UAC, и только по
  явному клику.
- **Linux**: GUI-процесс никогда не запускается от root целиком — вместо
  этого при подключении в TUN каждое привилегированное действие (создание
  TUN-адаптера, правка маршрутов/DNS, `wg-quick`/`awg-quick`) отдельно
  запрашивает пароль через `pkexec` (системное графическое окно PolicyKit).

## Как это устроено

Написать протокол VLESS или WireGuard "с нуля" — плохая идея (это
криптография и сетевой стек уровня ядра). Поэтому приложение — это GUI-
оболочка на Electron, которая генерирует конфиги и управляет проверенными
open-source движками (как это делают v2rayN / NekoRay / сама Amnezia), с
отдельной платформенной прослойкой для Windows/Linux — см.
[`src/platform/`](src/platform).

| Профиль | Движок | TUN | PROXY |
|---|---|---|---|
| `vless://` / `trojan://` | [Xray-core](https://github.com/XTLS/Xray-core) + [tun2socks](https://github.com/xjasonlyu/tun2socks) | Xray поднимает локальный SOCKS5, tun2socks превращает его в системный TUN-адаптер (Wintun на Windows, `/dev/net/tun` на Linux) | Xray поднимает локальный SOCKS5 **и** HTTP-инбаунд — никакого адаптера |
| AmneziaWG / WireGuard | Windows: [AmneziaWG для Windows](https://github.com/amnezia-vpn/amneziawg-windows-client) (вшит в приложение). Linux: системные `wg-quick`/`awg-quick` | Официальный бэкенд сам поднимает адаптер и маршруты | не поддерживается |

Xray-core/tun2socks **не входят в репозиторий** — вкладка «Движки» в
приложении качает официальные релизы с GitHub при первом запуске (кнопка
«Установить», ~30–50 МБ, работает без прав администратора/root — это просто
файлы в пользовательской папке). AmneziaWG для Windows, наоборот, **вшит
прямо в приложение** (`resources/amneziawg/`, см. `npm run fetch-amneziawg`
для обновления версии).

## Запуск (для разработки)

Нужен только [Node.js](https://nodejs.org) (проверено на v24).

```bash
npm install
npm start
```

Первый `npm install` скачает Electron (~200 МБ) — это нормально.

## Сборка установщика

```bash
npm run dist
```

На Windows соберётся `dist/My List VPN Setup X.Y.Z.exe` (NSIS). На Linux —
`dist/my-list-vpn-X.Y.Z.x86_64.rpm` (нужны системные `rpmbuild`/`fpm` —
electron-builder сам скажет, если их не хватает; **`.rpm` можно собрать
только на самой Linux-машине**, кросс-сборка с Windows на Linux не работает).

Иконка (`assets/icon.ico`/`.png`) уже сгенерирована скриптом
`build/generate-icon.js` (чистый Node, без внешних библиотек — просто
запустите `npm run gen-icon`, если захотите перерисовать).

## Установка на Fedora

```bash
sudo dnf install ./my-list-vpn-X.Y.Z.x86_64.rpm
```

Зависимости (`polkit`, `iproute`, `systemd-resolved`, `wireguard-tools`) rpm
подтянет через `dnf` автоматически — с ними доступны режим PROXY сразу и TUN
для VLESS/Trojan/обычного WireGuard.

Для **AmneziaWG** (конфиги с обфускацией Jc/Jmin/...) официального пакета в
репозиториях Fedora нет — нужен COPR:

```bash
sudo dnf copr enable <copr-репозиторий-amneziawg-tools>
sudo dnf install amneziawg-tools
```

(актуальный COPR ищите на странице проекта AmneziaWG — на момент написания
единого официального репозитория для Fedora ещё нет; без него приложение
работает нормально, просто конфиги с обфускацией TUN поднять не сможет —
подключение упадёт с понятной ошибкой).

## Публикация релиза на GitHub

Бейдж обновлений в приложении (см. `src/core/updateChecker.js`) сверяется
с [GitHub Releases](https://github.com/ndzeone/my_list_vpn/releases) этого
репозитория. Чтобы выпустить новую версию:

```bash
# 1. Поднять "version" в package.json
# 2. Собрать установщик(и)
npm run dist
# 3. Закоммитить и запушить код в main (обычным git push)
# 4. Создать тег, GitHub Release (с автосгенерированным описанием из
#    коммитов с прошлого тега) и залить установщик как ассет:
npm run release
```

`npm run release` (`build/release.js`) сам создаёт тег `vX.Y.Z` по версии из
package.json, пушит его, генерирует красивое описание релиза (✨ Новое /
🐛 Исправления / 🔧 Прочее — из сообщений коммитов) и через GitHub REST API
публикует релиз с установщиком из `dist/`. Нужен файл `.release-token` в
корне проекта (в `.gitignore`, никогда не коммитится) — GitHub fine-grained
Personal Access Token с правом **Contents: Read and write** на этот
репозиторий (Settings → Developer settings → Fine-grained tokens на
github.com).

⚠️ **Не выполняйте `build/release.js` через `node -e "require(...)"` или
любой другой способ, кроме `npm run release`** — файл вызывает `main()`
сразу при загрузке, без охраны `require.main === module`, и любое
`require()` реально запушит тег и опубликует релиз на GitHub.

## Использование

1. При первом запуске — экран **«Создать локальный аккаунт»**: email +
   пароль (только на этом компьютере, без сервера). При следующих запусках
   — экран входа с тем же паролем.
2. **Серверы** (в левом меню) → **«+ Добавить конфиг»**. Вставьте ссылку
   `vless://...` или `trojan://...`, **или** содержимое `.conf`
   AmneziaWG/WireGuard целиком (можно и JSON-экспорт из Amnezia — программа
   вытащит конфиг автоматически), **или** ссылку-подписку (http/https) — тогда
   добавятся сразу все серверы, которые по ней найдутся.
3. **Настройки → Движки** — для VLESS/Trojan установите Xray-core (разовая
   загрузка). Для WireGuard/AmneziaWG на Windows ничего ставить не нужно
   (встроено); на Linux нужны системные `wg-quick`/`awg-quick` (см.
   «Установка на Fedora» выше).
4. На главном экране выберите **TUN** или **PROXY**, выберите сервер и
   нажмите большую кнопку питания. Если что-то зависло на «Подключение…» —
   кнопка **«Отменить подключение»** появится там же, а если и это не
   помогло — **Настройки → О программе → «Сбросить состояние подключения»**.
5. **Настройки → Общие** — автозапуск с системой, автоподключение к
   последнему серверу, поведение окна при закрытии, интервал проверки
   обновлений. **Настройки → Сеть** — DNS/IP TUN-адаптера, порты SOCKS/HTTP
   для PROXY, авто-включение системного прокси (Windows).

Один профиль подключён — остальные заблокированы для подключения, пока
активный не отключён (как и должно быть для системного TUN).

## Структура проекта

```
main.js                  Electron main-процесс, IPC, трей
preload.js                 Безопасный мост IPC для рендерера (contextBridge)
renderer/                  UI (чистые HTML/CSS/JS, без сборщика) — рейл-навигация, вкладки настроек
src/parsers/                 vless.js, trojan.js, wireguard.js — разбор ссылок/конфигов
                                xrayStream.js — общая часть vless/trojan (streamSettings)
src/platform/               Windows/Linux-специфичный код за единым интерфейсом
  index.js                    выбор ./win или ./linux по process.platform
  win/                          UAC, netsh/route, реестр (системный прокси), amneziawg.exe
  linux/                         pkexec, ip/resolvectl, wg-quick/awg-quick, без авто-прокси
src/core/
  paths.js                    все пути userData/движков (платформо-зависимые расширения файлов)
  coreManager.js               скачивание Xray/tun2socks (+ wintun на Windows)
  processCleanup.js             чистка зависших процессов от прошлого краша при старте
  subscription.js               загрузка и разбор ссылок-подписок (много ключей разом)
  elevation.js                  тонкий диспетчер к src/platform/*/elevation.js
src/engine/
  xrayEngine.js                процессы xray + tun2socks: startTun() и startProxy()
  wgEngine.js                   оркестратор WireGuard/AmneziaWG, делегирует src/platform/*/wgBackend.js
  proxyManager.js                тонкий диспетчер к src/platform/*/proxySystem.js
  tunController.js                оркестратор: выбор движка/режима, состояние, forceReset()
  pingHelper.js                    лёгкий TCP-пинг сервера для карточки
resources/amneziawg/       amneziawg.exe + wintun.dll, вшиты в Windows-установщик (build.extraResources)
build/fetch-amneziawg.js    обновляет resources/amneziawg/ из нового релиза (npm run fetch-amneziawg)
build/release.js             публикация релиза на GitHub с автогенерацией описания
src/store/
  profileStore.js               серверы, зашифрованные ключом аккаунта
  accountStore.js                 локальный аккаунт (email/пароль → ключ)
  settingsStore.js                сеть (TUN/PROXY) + поведение приложения
build/generate-icon.js       генератор assets/icon.png + icon.ico
```

## Известные ограничения / что доработать при желании

- IPv6 не обрабатывается отдельно (только IPv4-маршруты).
- Для vless-профиля обходной маршрут к серверу считается один раз при
  подключении: если DNS-адрес сервера меняет IP на лету, потребуется
  переподключение.
- Один активный туннель одновременно (сознательное упрощение, как у
  большинства клиентов).
- Linux-ветка (`src/platform/linux/`) написана и проверена статически
  (`node --check`, юнит-тесты диспетчера), но не прогонялась на реальной
  Fedora — при первом использовании возможны шероховатости с `pkexec`/
  `resolvectl`/именами интерфейсов, пишите issue с логом из журнала
  соединения.
